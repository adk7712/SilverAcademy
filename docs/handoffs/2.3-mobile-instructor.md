## What was built
- **Dashboard**: three oversized buttons (96dp+, `ui/instructor/BigActionButton`), profile state card (`ProfileStateCard`, links to `InstructorProfileForm`), "My workshops" list (direct query `workshops where instructorId == uid order by createdAt desc`, reloaded on focus) with status badge and next step: DRAFT -> Request Venue, PENDING_VENUE -> View venue request, OPEN/COMPLETED -> View roster. Create Workshop and Request Venue are disabled until the profile is APPROVED.
- **Create Workshop**: title, description, category (Select), max capacity, materials, volunteers yes/no + slots; inline errors from `validateWorkshopForm` (shared limits + `workshopsSchemas.createWorkshopInput` as final check). Not-approved profile shows a gate card with a link to the profile form. On success it `replace`s to `VenueRequest {workshopId}`.
- **Venue Request**: loads workshop, own requests for it, `facilities` and collection-group `slots` (AVAILABLE, future; existing index), groups per venue (`buildVenueOptions`: drops slots starting within `VENUE_REQUEST_MIN_LEAD_MIN`, flags venues too small). List view always; when `MapProvider.isAvailable()` a List/Map toggle appears and the map is a schematic pin plot (`projectPins`, no tiles). Pick venue -> pick slot -> `venues-requestVenue`. Latest request card: status badge, decision reason, info question + reply (`venues-respondToInfoRequest`), withdraw (`venues-withdrawVenueRequest`). `SLOT_CONFLICT`/`SLOT_UNAVAILABLE`/`SLOT_IN_PAST` clear the selection, reload slots and show "choose another time"; CONFLICTED/REJECTED/WITHDRAWN on a DRAFT workshop show the status and allow a new pick.
- **Instructor Profile**: bio, expertise (checkbox chips), years; status badge, reviewer reason on REJECTED/REQUIRES_REVISION; editable only when none/REJECTED/REQUIRES_REVISION; submits `users-submitInstructorProfile`.
- Tests (Jest `mobile` project): `instructorWorkshopLogic.test.ts`, `instructorProfileLogic.test.ts`, `venueRequestLogic.test.ts`.
