## Data model decisions
- Singpass uids: `sp_` + sha256(sub)[0..20] (same derivation as architecture 5.1). Roles mirror `auth-exchangeSingpass`: LEARNER, plus SENIOR_INSTRUCTOR when age >= 50 at seed time; volunteer = VOLUNTEER.
- Staff uids `st_<staffUserId>`, email `<staffUserId>@staff.silveracademy.test`, custom claim `roles` set on every Auth user.
- Voucher inventory id = sha256(normalised code); tier id `${provider}_${denomination}`; `pointsCost = denomination * POINTS_PER_SGD`.
- Counters are derived from the seeded data, not hand-typed: `seatsTaken`, `attendedCount`, `volunteersAssigned`, tier `counts`, wallet `balance`/`lifetime*` (from ledger), instructor `ratingSum/ratingCount` (from feedback). A rerun recomputes them identically.
- Ticket codes are fixed Crockford strings (validated); QR payloads are signed with the dev `QR_HMAC_SECRET` default, matching architecture 4.2 (`SA1.<bookingId>.<sig22>`).
- Dates are relative to the run time on the SG calendar, so a rerun shifts "upcoming" and "past" windows forward. Ids and content stay the same.

## Open issues
- **Shared enum typing defect (0.4 follow-up, not fixed here):** `packages/shared/src/enums.ts` `def` is `<T extends readonly string[]>(values: T) => values`, which infers `string[]`, so every enum type (`BookingStatus`, `VoucherStatus`, `WorkshopStatus`, ...) collapses to `string`. Probe confirmed `const x: BookingStatus = 'NOT_A_STATUS'` compiles. Fix is `const def = <const T extends readonly string[]>(values: T) => values;` and then re-run shared tests and typecheck across workspaces. The seed works around it with local literal unions (`bookings.ts` status, `vouchers.ts` counts).
- `npm run seed` needs the two emulator env vars set on the command line. Could be wrapped with `firebase emulators:exec` later if one-command seeding is wanted.
- Seeded QR tickets verify only once functions `qrSigner` (1.3) uses the same secret as the seed default.
- Singpass Auth users are created without a provider link; real login mints custom tokens (1.1). Demo only.
- Mock DOBs are fixed: `senior-49-edge` turns 50 on 2027-06-30. A rerun after that gives that learner the SENIOR_INSTRUCTOR role, while the fixtures stay the same.
- Staff passwords are emulator defaults in `guard.ts`. They are not secrets, but do not reuse them outside the emulator.
