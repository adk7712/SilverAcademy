## What was built
- **redeemVoucher** (arch 4.4): one `runTx`. Reads `instructorProfiles/{uid}`, `voucherTiers/{tierId}`, `wallets/{uid}`, query `voucherInventory where tierId, status == AVAILABLE orderBy uploadedAt limit 1`. `decideRedeem` order: PROFILE_NOT_APPROVED -> TIER_NOT_FOUND (missing/inactive) -> INSUFFICIENT_POINTS `{ required, balance }` -> OUT_OF_STOCK. Writes: voucher CLAIMED (claimedBy, claimedAt = injected clock), wallet + `ledger/redeem_{voucherId}` via `writeLedgerTx`, tier `counts.AVAILABLE -1 / CLAIMED +1` (FieldValue.increment), audit `VOUCHER_REDEEM` (no code). Profile is read inside the tx (not pre-tx as arch says; same result, one fewer round trip).
- **listMyVouchers**: `claimedBy == uid orderBy claimedAt desc` (existing index); returns codes.
- **uploadVouchers** (arch 4.5): one tx. Reads the distinct referenced tiers (`tx.getAll`), `planUpload` (= shared `classifyUploadRows` + `sha256` doc ids), `tx.getAll` of survivor ids, `decideUpload` (existing -> DUPLICATE_EXISTING). Writes: `tx.create` each accepted voucher (`uploadedAt` = clock), tier `counts.AVAILABLE += n`, `voucherUploads/{batchId}` (masked rejects), audit `VOUCHER_UPLOAD` with counts. Rejected rows are sorted by row number and masked (`****1234`).
- **setVoucherStatus**: `requireReason` (REASON_REQUIRED, before any read) -> tx: NOT_FOUND -> VOUCHER_NOT_AVAILABLE (details `{ status }`) -> voucher status + `statusReason`, tier counts moved, audit `VOUCHER_STATUS_CHANGE`.
- **upsertTier**: id `${provider}_${denomination}`; counts zeroed on create and untouched on update; audit `VOUCHER_TIER_UPSERT` (details `created`).
- **listInventory**: equality filters (tierId, status) + `orderBy(documentId)`, `startAfterId` cursor, default limit 50 (`INVENTORY_PAGE_DEFAULT`); masked codes only. Grouping by provider/denomination/status comes from `voucherTiers.counts` (client read).

## Open issues
- **>400 rows** is rejected by the shared zod schema (`.max(MAX_UPLOAD_ROWS)`) as `INVALID_INPUT` (fieldErrors.rows), not `UPLOAD_TOO_LARGE` as functions.md says. Fixing it needs a shared schema change (drop `.max`, check in the handler) and the shared test that asserts 401 rows is invalid. The web app should pre-check row count anyway. `UPLOAD_TOO_LARGE` is still thrown when accepted + tier writes + 2 would exceed 500 (many distinct tiers in one file).
- Tier ids are case-sensitive (`provider` not uppercased) in both upsert and upload, consistent with shared `voucherTierId`.
- `listMyVouchers` returns every voucher ever claimed by the caller (no paging); fine for the demo.
- `toHttpsError` logs unknown errors with the raw error object; voucher code paths never put a code into an error, but keep it that way.
