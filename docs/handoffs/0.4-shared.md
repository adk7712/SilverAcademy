## Interfaces exposed
Single barrel `@silveracademy/shared`. Schemas are namespaced: `authSchemas`, `usersSchemas`, `workshopsSchemas`, `bookingsSchemas`, `attendanceSchemas`, `venuesSchemas`, `vouchersSchemas`, `reportsSchemas`; plus common builders (`isoDateTimeSchema`, `toFieldErrors`, ...). Handlers: `CALLABLES[name].input.safeParse(data)`; on failure throw `AppError(INVALID_INPUT, ..., { fieldErrors: toFieldErrors(err) })`. Apps' `services/callables.ts` can type via `CallableInput<N>`/`CallableOutput<N>`.

## Deviations from architecture.md / functions.md
- Not implemented here (deferred to their owning tasks): `OneMapProvider`, `StubMapProvider`, `createMapProvider`, map `fixtures.ts` (task 1.6, interface + `haversineKm` are here); MOCK profile `FAIL`/`DOWN` are exposed as constants (`MOCK_FAIL_PROFILE_ID`, `MOCK_DOWN_PROFILE_ID`), not as list entries.
- Layout: `schemas/` is namespaced on the barrel (to avoid duplicate export names), `logic/` and `auth/` as in arch 1.3; `HttpsCode` type and `httpsCodeFor` added to `errors.ts`.
- `recordAttendanceInput` is a union of two strict objects (exactly one of `qrPayload`/`ticketCode`).
- zod refinements encode REASON_REQUIRED-style rules at input level (reject/revision/flag/suspend reasons, REQUEST_INFO message, CANCELLED reason, incident AWAITING_INFO/RESOLVED text, CP `orgName`). Handlers must still re-check; the error code is `INVALID_INPUT` from schema, not `REASON_REQUIRED`, if the schema is applied first. Decide in 1.x whether to skip these refinements to preserve the documented error codes.
- `createWorkshopInput` additionally requires `volunteerSlots >= 1` when `needsVolunteers` (doc only said 0 when not needed). Max `volunteerSlots` 5.
- New constants not in arch table (limits for schemas): `SG_UTC_OFFSET_HOURS, MS_PER_MINUTE, MS_PER_DAY, POSTAL_CODE_LENGTH, FACILITY_*, AMENITIES_MAX, AMENITY_MAX_LENGTH, VOUCHER_LIST_LIMIT_MAX, VOUCHER_MASK_*, VOUCHER_DENOMINATION_MAX, VOUCHER_REASON_MAX, CROCKFORD_ALPHABET, TICKET_CODE_GROUP, QR_BOOKING_ID_MAX, QR_SIGNATURE_LENGTH, FEEDBACK_*, ATTACHMENT_CONTENT_TYPES, INCIDENT_TEXT_MAX, INCIDENT_REF_REGEX, DISPLAY_NAME_MAX, INSTRUCTOR_BIO_MAX, EXPERIENCE_YEARS_MAX, REASON_MAX, STAFF_USER_ID_MAX, STAFF_PASSWORD_MIN, ORG_NAME_MAX, RECO_DEFAULT_LIMIT, EARTH_RADIUS_KM, MAP_SEARCH_DEFAULT_LIMIT`. Values for these are my choices (arch gave none); adjust freely.
- `recommendWorkshops` excludes full workshops (arch only gave the score formula) and defaults to `RECO_DEFAULT_LIMIT` (5).
- `QR_SIGNATURE_LENGTH` and `INCIDENT_REF_REGEX` follow arch 4.2 / 2.2 (Crockford base32 incident suffix).
- `users-markNotificationRead`/`listMyVouchers` inputs are strict empty/one-field objects.
- `getRosterOutput.workshop.venue` is `{ name, address } | null` (functions.md said `venue` without shape).
