## Agent / model
Sonnet, 2026-10-19.

## What was built
- **Scanner flow**: workshop picker (instructor: own workshops with status OPEN/COMPLETED via direct read; volunteer: own `volunteerAssignments` with status ASSIGNED; both merged if the user holds both roles; open check-in window sorted first and badged as a hint only) -> `ScannerPanel` with Expo Camera `CameraView` (QR only), permission request / denied (settings link) / mount-error fallback to manual ticket-code entry, large result banner (display-size title, high contrast), haptics via `expo-haptics` (best effort), no sound.
- **Result banners**: success (learner name, workshop, "+N point" only for the owning instructor), and distinct errors for INVALID_QR (also raised client-side when `parseQrPayload` fails, no server call), TICKET_NOT_FOUND, WRONG_WORKSHOP, NO_BOOKING, ALREADY_ATTENDED (learner name and time from `details`), NOT_AUTHORISED (NOT_AUTHORISED_FOR_WORKSHOP / NOT_ASSIGNED / PERMISSION_DENIED), WINDOW_CLOSED (SESSION_NOT_ACTIVE), NETWORK, other (central `errorMessage`).
- **Continuous scanning**: success auto-returns to scanning after 2.5 s (or tap "Scan next"); errors wait for a tap. Double submits are prevented by a synchronous `busy` ref, the reducer (SUBMIT only from `scanning`), and a 3 s same-value cooldown gate. Manual code is sent as typed (trimmed); the server normalises.
- **Roster**: `bookings-getRoster` summary (attended/total, seats), learners with Attended/Registered badge and ticket code, volunteers, refresh button, shortcut to the scanner for that workshop.
- Pure logic tested: `scanLogic.test.ts` (state machine, debounce gate, error classification, points rule), `workshopOptions.test.ts`, `rosterLogic.test.ts`.
