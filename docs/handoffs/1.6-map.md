# Handoff: 1.6 MapProvider (OneMap + stub)

## What was built
`packages/shared/src/services/map/`: `OneMapProvider` (REST search + postal geocode, AbortController timeout, optional token), `StubMapProvider` (10 fixtures, deterministic, optional simulated outage), `createMapProvider(cfg)`, `fixtures.ts` (`MAP_FIXTURES`), `mapErrors.ts` (`mapUnavailable`, `isMapUnavailable`), `map.test.ts` (9 tests, mocked fetch, no network). Exported via `services/index.ts` -> `@silveracademy/shared`.

## Interfaces
- `createMapProvider({ kind?, timeoutMs?, fetchImpl?, token?, env? })`; kind falls back to `env.MAP_PROVIDER`, default `stub`. Token from `cfg.token` or `env.ONEMAP_TOKEN` (sent as `Authorization`; search works without it).
- Failures (network, timeout, non-2xx) reject with `AppError('MAP_UNAVAILABLE')`; UI uses `isMapUnavailable(e)` or `await isAvailable()` to switch to list view (#1-3 Ex2). `isAvailable()` never throws.
- `StubMapProvider.tileUrlTemplate()` is null (list view). `new StubMapProvider({ unavailable: true })` simulates an outage for demos/tests.
- Distance sorting: use existing `haversineKm` / `sortByDistance` from `logic/` on the geocoded/device location.

## Verification
typecheck, lint, `npm test` (8 suites, 59 tests) pass.

## Notes / deviations
- Fixtures are 10 (task brief), not ~20 as architecture.md says; seed (0.5) may keep its own list. Factory does not read `process.env` itself; callers pass `env`.
- Search returns upstream OneMap order; no reverse geocode (not in the MapProvider interface, so not added).
- Only `isMapUnavailable` checks by code; callers should not rely on message text.
