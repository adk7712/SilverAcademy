# Handoff: 2.9 Web Admin part 1 (accounts, workshops, instructor review)

## Task
Replace the placeholder pages for Manage Accounts (UC #5-1), Manage Workshops (UC #5-2) and Instructor Review (UC #5-5). Voucher inventory and incident queue belong to 2.10.

## Agent / model
Sonnet, 2026-10-19.

## What was built
- **Routes unchanged**; each page uses nested `<Routes>`: `/admin/accounts` (list) and `/admin/accounts/:uid` (detail); `/admin/workshops` and `.../:id`; `/admin/instructor-review` and `.../:uid`.
- **users**: `AccountList` (name prefix search via `displayNameLower` range read, plus client-side Role / Status / Flagged filters, sortable table), `AccountDetail` (roles, status, flag, profile, instructor profile if any; Flag / Unflag / Suspend / Reactivate through `ReasonDialog`; no actions for ADMIN targets, with a note). `PendingProfileList` (status == PENDING, oldest first) and `ProfileReviewDetail` (Approve, Reject, Request revision; reason required for the last two).
- **workshops**: `WorkshopList` (search title/instructor, status and category filters), `WorkshopDetail` (all fields, venue, volunteers, cancel reason), `WorkshopEditForm` (title, description, category, materials, capacity; sends only changed fields; capacity disabled once started/finished, minimum = seats booked), `StatusDialog` (Complete, Archive, Unarchive, Cancel). Cancel requires a reason; when bookings are affected an impact warning with a required acknowledgement checkbox is shown and `confirmImpact: true` is sent.
- **Validation before submit**: `checkReason` (users) and `checkStatusForm` / `checkEditForm` (workshops) return field errors without calling the backend.
- **Error handling**: `classifyFailure` maps to `errorMessage`; STALE_VERSION / NOT_FOUND / INVALID_TRANSITION etc. reload the record; UNAUTHENTICATED / ACCOUNT_SUSPENDED call `useSession().logout()`; CANNOT_TARGET_ADMIN shows the central message in the dialog.
- Layering: `ui -> controller (hooks + pure rules) -> repo`. Feature strings: `features/users/strings.ts`, `features/workshops/strings.ts`.

## Open issues

- Admin reads need Firestore indexes only for single-field orderings (default); role/status filters are client-side over at most 200 users / 300 workshops, so very large datasets are not fully searchable. Name search is prefix on lowercase display name only.
- Admin cancel/archive preview uses the client clock for "upcoming"; the backend is authoritative and its `ACTIVE_BOOKINGS_CONFIRM_REQUIRED` error triggers a refresh.
- `useLoad` and `formatTimestamp` are duplicated in both features to keep them independent; could move to a shared web util later.
- Central strings, routes and design kit were not changed; no changes needed.
- Request revision is also exposed (backend supports it) although the task named only Approve / Reject.
- Workshop edit does not warn that title/description edits are not propagated to existing bookings' snapshots (1.7 open issue).
