## How to add a handler (the recipe)
1. Make sure the callable exists in `packages/shared/src/callables.ts` (`CALLABLES['<feature>-<name>']` with input/output zod schemas). The wrapper takes both schemas from there; do not re-declare them.
2. `controller/decide<Thing>.ts`: pure function `(snapshots, input, uid, now) => decision | throws AppError`. Imports only `@silveracademy/shared` and `../../common/clock` (ESLint forbids firebase imports in controller). The check order in architecture 4.x is the contract; assert it in a unit test.
3. `repo/<thing>Repo.ts`: Admin SDK. Use `runTx(db, async (tx) => { reads with tx.get; const d = decideX(...); writes })`. Inside the tx use `writeAuditTx(db, tx, ...)`, `notifyTx(db, tx, ...)`, `writeLedgerTx(db, tx, uid, walletData, ...)`; deterministic ids from `ids.*`; collection names from `COL`/`refs`. Use `FieldValue.serverTimestamp()` for `createdAt/updatedAt`, `Timestamp.fromDate(now)` when the time must equal the injected clock. Bump `version` on admin-editable docs.
4. `handlers/<name>.ts`:
   ```ts
   export const bookWorkshopCallable = defineCallable(
     'bookings-bookWorkshop',
     { roles: ['LEARNER'] },                 // or { roles: ['ADMIN'], auditOnDeny: true } or 'public'
     async ({ input, caller, now, db }) => bookWorkshop(db, caller, input, now),
   );
   ```
   The wrapper already did: requireCaller (UNAUTHENTICATED -> ACCOUNT_SUSPENDED -> PERMISSION_DENIED), zod parse (`INVALID_INPUT` + `details.fieldErrors`), output schema check (violation = `INTERNAL`), AppError -> HttpsError (`details.code`), ABORTED -> BUSY_TRY_AGAIN. `caller` = `{ uid, user, roles }` from `users/{uid}`. Export a plain `async function` next to the callable so tests can call it with fake/real deps.
5. `<feature>/index.ts`: `export { bookWorkshopCallable as bookWorkshop } from './handlers/bookWorkshop';` (the export name is the deployed suffix: `bookings-bookWorkshop`). `src/index.ts` already has `export * as <feature>`.
6. Handlers must themselves check the conditional-required fields that no longer live in the schema: REJECT/REQUEST_REVISION reason, FLAG/SUSPEND reason, REQUEST_INFO message, CANCELLED reason, incident `infoRequest`/`resolution`, voucher status reason -> `AppError('REASON_REQUIRED')`.
7. Tests: unit-test `decide*` and any pure helpers (`*.test.ts`, Jest `functions` project). For transactions/concurrency write `*.emu.test.ts` (runs under `npm run test:emulator`; see `auth/auth.emu.test.ts` for init of firebase-admin against emulators). `runCallable(def, req, deps)` lets you test the wrapper path with fake `loadUser`.
8. `npm run build -w @silveracademy/functions` is part of `npm run emulators`; with emulators running use `build:watch`.

## Interfaces exposed
- Claims on every ID token: `{ roles: Role[], status: AccountStatus }`. Singpass: in the custom token and persisted. Staff: persisted by `recordStaffLogin` SUCCESS; the web app must then `getIdToken(true)`. Anything that changes roles/status must re-set claims (`setCustomUserClaims`) and `revokeRefreshTokens` (users module, task 1.7).
- `verifyQr(payload)` returns the bookingId or throws `INVALID_QR`; `signQr(bookingId)`; both use `QR_HMAC_SECRET` (dev default `dev-only-change-me` in emulators; matches the seed).
- Writing ledger: read wallet with `tx.get` first, pass `snap.data()` to `writeLedgerTx`; it uses `tx.create` on `ledger/{entryId}` so a replay fails.
- `refs.*` typed refs use pass-through converters; `Timestamp`/`FieldValue` writes are accepted by the types (`WithFieldValue`).
- Rules: clients can only query workshops with `where('status','==','OPEN')` (or `in` over OPEN/COMPLETED/CANCELLED) or `where('instructorId','==',uid)`; unconstrained list works only for ADMIN. Community partners cannot read workshops at all (RBAC matrix). Everything else follows architecture 3.4; `voucherInventory` is unreadable even by admin.

## Open issues
- **Seed**: `firebase/seed/apply.ts` sets claims `{ roles }` only (no `status`), so seeded Singpass users hit the rules as non-active until they log in through `auth-exchangeSingpass` (which re-sets claims; fine for the demo flow) and staff until `recordStaffLogin` SUCCESS. Cleaner fix: seed should set `{ roles, status: 'ACTIVE' }`.
- `recordStaffLogin` FAILURE/BLOCKED is public and unthrottled, so anyone can write audit entries (length-capped details). Rate limiting / App Check is out of scope for the prototype.
- Failed-login audit entries have a null actor by design; the typed `userId` is in `details.userId`.
- Real Singpass is not implemented: `AUTH_MODE=singpass` returns `SINGPASS_UNAVAILABLE`.
- `auth-exchangeSingpass` does not audit Singpass logins (not required by functions.md).
- Jest root `npm test` runs a `packages/shared` map test (`map.test.ts`, task 1.6, in progress by another agent) that was logging an unhandled `MAP_UNAVAILABLE` rejection in one run; unrelated to 1.1 and green in the final run.
- Storage `create`-only rule needed an explicit `resource == null` guard; the emulator allowed overwrites without it.
- The emulator warns "node 22 vs global 26"; harmless.
