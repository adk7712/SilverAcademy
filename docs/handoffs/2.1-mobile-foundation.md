## Task
Mobile app shell for Phase 2: app entry, role/mode-aware navigation, design system, Firebase client + typed callables + error mapper + central strings, and the auth feature (UC #0-1, FR 1.3, ADR-006/008).

## Agent / model

## What was built
- **Design system** `apps/mobile/src/design` (import from `../../design`): tokens (high-contrast colours, spacing, radius, sizes, type scale), `ThemeProvider`/`useTheme()` with a user-adjustable text size (`FONT_SCALES` 1 / 1.25 / 1.5, persisted in AsyncStorage `prefs:fontScale:v1`). Components (all targets >= 44dp, most 48-56): `AppText`, `Button`, `IconButton`, `Card`, `TextField`, `Select`, `Segmented` (extra), `Header`, `Screen`, `ListItem`, `Badge`, `ErrorBanner`, `EmptyState`, `LoadingState`, `ToastProvider`/`useToast()`, `PlaceholderScreen`. `Screen` draws the header, safe area and (inside a stack, when not at its root) a Back button automatically.
- **Services** `apps/mobile/src/services`: `firebase.ts` (app/auth/firestore/functions; connects to emulators when `EXPO_PUBLIC_USE_EMULATORS=true`, host `EXPO_PUBLIC_EMULATOR_HOST`), `callables.ts` (`callFunction(name, input)` typed by `CallableInput/Output`, strips `undefined` keys, throws `AppError`), `errors/toAppError.ts` (reads `details.code`; connectivity failures become `INTERNAL` with `details.reason === 'NETWORK'`), `errors/errorMessage.ts` (`errorMessage(e)` -> user text), `storage.ts` (never-throwing AsyncStorage JSON), `auth/MockSingpassProvider.ts` + `createAuthProvider.ts`.
- **i18n** `apps/mobile/src/i18n`: `strings` (typed catalogue, English), `format(template, params)`. One file per area in `en/` (common, nav, auth, errors, and one per feature) so feature agents never edit the same file. `errors.ts` is an exhaustive `Record<AppErrorCode, string>`.
- **Auth feature** `features/auth`: login screen with mock Singpass picker (`MOCK_SINGPASS_PROFILES` + "simulate failure/down" buttons for FAIL/DOWN), error banner for `SINGPASS_AUTH_FAILED/UNAVAILABLE`, first-login Join as Learner / Volunteer (on `REGISTRATION_REQUIRED` the call is repeated with `registerAs`), `SessionProvider`/`useSession()` (claims `{roles,status}`, display name from own `users/{uid}`, mode, `refresh()` with forced token refresh also on app foreground, `signOut()`), `ModeToggle` (shown above the tabs only when roles include LEARNER and SENIOR_INSTRUCTOR; persisted per user in AsyncStorage and mirrored best-effort to `users-updatePreferences.lastMode`), `AccountPanel` (name, roles, text size, logout), `SessionBlockedScreen` (non-ACTIVE status, or staff-only roles).
- **Navigation** `apps/mobile/src/navigation`: `RootNavigator` (loading / login / blocked / `MainShell`), `MainShell` (mode toggle + tabs), `LearnerTabs`, `InstructorTabs`, `VolunteerTabs`, `createStack`, typed route table `types.ts`, hooks `useAppNavigation()` / `useAppRoute<'Name'>()` (import from `../../navigation`). Route names are unique app-wide.
- **Feature placeholders**: 17 screens exported from each feature's `index.ts` (table below). The three Instructor dashboard buttons already navigate.
- Tests: `jest` project `mobile` (added to root `jest.config.js`, ts-jest transpile-only, pure logic only): error mapper/messages, session logic (claims, 50+ mode eligibility, mode resolution), login picker + mock provider, font scale, `stripUndefined`.

## Recipe for a feature agent
1. Screen in `features/<f>/ui/`, wrapped in `<Screen title=...>`; no Firebase or repo imports (ESLint enforces).
2. Controller hooks in `controller/` (zod from shared, `useSession()` from `../../auth` for `uid`/`roles`). Repo in `repo/`: `import { callFunction } from '../../../services/callables'` and `firestore` from `../../../services/firebase`; no business rules.
3. Strings: add keys to `src/i18n/en/<feature>.ts`; show failures with `errorMessage(e)` (`services/errors/errorMessage`) in an `ErrorBanner`; success feedback with `useToast().show(msg, 'success')`.
4. Use `strings.*`/tokens, never literals; tap targets via the design components.
5. Firestore client reads are subject to rules (workshops must filter by `status` or `instructorId`).
6. Pure logic (anything with no `react-native`/Firebase imports) can be unit tested in the Jest `mobile` project (`*.test.ts` next to the file). Component tests are not set up.

## Open issues
- Tab bars use text labels only (no icon set installed); consider an icon pack in 2.11.
- Text size is local only (AsyncStorage); `prefs.fontScale` on the server is not synced. Mode is mirrored to `prefs.lastMode` best-effort.
- Mode toggle is the only account switcher: a user holding VOLUNTEER plus LEARNER would get Learner shell only (server never produces that combination).
- Seeded Singpass users lack the `status` claim until login; the shell treats a missing status as ACTIVE.
- `expo start` rewrites `apps/mobile/tsconfig.json` formatting; run Prettier afterwards.
- No component/render tests (only pure logic); Jest cannot import `react-native` modules in the `mobile` project.
- Metro served a stale module once during dev after edits; `expo start -c` fixed it.
