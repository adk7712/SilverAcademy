## What was built
- **Firebase client** `src/services/`: `env.ts` (`readEnv`, VITE_USE_EMULATORS default on, ports auth 9099 / firestore 8080 / functions 5001 / storage 9199), `firebase.ts` (auth, firestore, functions in `FUNCTIONS_REGION`, storage; connects emulators), `callables.ts` (`callFunction(name, input)` typed by `CALLABLES`, throws `AppError`), `errors.ts` (`toAppError` via `details.code`, fallback on SDK code; `errorMessage(e)`; `fieldErrorsOf(e)` for `INVALID_INPUT`; `isNetworkError`). Import via `src/services/index.ts`.
- **Strings** `src/strings/` (`strings.errors` has a message for every `AppErrorCode` plus `NETWORK`; a test enforces completeness). Add new copy as new sections in `strings/index.ts`.
- **Design kit** `src/design/` (import from `../../design`; tokens in `tokens.css`, `--touch-min` is set from shared `MIN_TOUCH_TARGET_PX`): `Button` (primary/secondary/danger/ghost, `busy`), `Table` (columns `{key, header, render, sortValue?}`, `rows`, `rowKey`, `caption`, `pageSize`, `loading`, `empty`; sorting via aria-sort header buttons, pagination), `TextField/TextAreaField/SelectField/CheckboxField` (`label`, `hint`, `error`, `required`; pass `fieldErrorsOf(err).<field>` as `error`), `Modal`, `ConfirmDialog` (`tone="danger"`, `busy`), `Badge` (tone), `Alert`, `ErrorBanner` (`error`, `onRetry`), `EmptyState`, `Spinner`, `ToastProvider` + `useToast().show(msg, tone)`, `PagePlaceholder`. Layout collapses the sidebar below 64rem (tablet portrait).
- **Auth** `features/auth`: `LoginPage`, `SessionProvider`/`useSession()` (`state`, `login`, `logout`), pure `controller/guards.ts` (`decideGuard`, `parseClaims`, `toSessionUser`, `staffEmail`), `controller/staffLogin.ts` (`performStaffLogin` with injected deps: sign in, `auth-recordStaffLogin` SUCCESS/FAILURE/BLOCKED, then `getIdToken(true)` and claims check), `repo/authRepo.ts` (only Firebase Auth code). A session exists only for `status == ACTIVE` accounts with ADMIN or COMMUNITY_PARTNER claims. Failed logins clear the form and show "Invalid Credentials. Access Denied"; disabled accounts show "Account suspended, contact the platform team."
- **App** `src/app/`: `paths.ts` (`PATHS`, `homePathFor`, `resolveLanding`), `routeConfig.tsx` (single route table, used by router and sidebar), `RequireRole.tsx`, `AppLayout.tsx` (sidebar by role, logout, skip link), `App.tsx`. Routes are mounted as `<path>/*`, so a feature can use nested `<Routes>` inside its page (e.g. `/admin/accounts/:uid`) without touching routing.

## Rules for feature agents
- Replace the page body but keep the exported component name and `index.ts` export; do not edit `app/`, `design/`, `services/`, `strings/` structure. Adding new exports to `design/` or new sections to `strings/index.ts` is expected but coordinate if two agents do it at once (suggest: each adds its own strings file `strings/<feature>.ts` and one spread line in `strings/index.ts`).
- Layering: `ui/` -> `controller/` -> `repo/`; ui must not import firebase or repo (ESLint). Mutations use `callFunction(...)` (put in repo); reads use `firestore` from `services` in `repo/`.
- Pass the doc `version` as `expectedVersion` where the API requires it; show errors with `ErrorBanner`/`errorMessage`, field errors with `fieldErrorsOf`.
- After a callable returns `UNAUTHENTICATED` or `ACCOUNT_SUSPENDED` mid-session, call `useSession().logout()`.
